# 0.1.0 本地验收记录

验证日期：2026-09-22。平台：Windows x64、Python 3.10.8。以下区分自动化、实际模型、可见界面和发布状态，不把其中一项替代另一项。

## 自动化

`python -m pytest -q`：**41 passed**。另通过 `node --check src/framepulse/web/app.js` 与 Python compileall。两个警告来自 Starlette 测试客户端的依赖弃用提示，不是应用断言失败。

覆盖：

- 实际 FFmpeg 编码的三色 3 镜样片：36 帧、24 fps、总长 1.5 秒；切点准确得到 0.5 秒和 1 秒，各镜证据图的颜色与所属范围相符。
- 非零首 PTS（2 秒）与 VFR：首帧归零；实际第 13/14 帧分别为 500000/583333 微秒，保留原 PTS 和 time_base。
- 持续条纹运动不过度逐帧切镜；中文、空格路径；EXIF 旋转；全透明彩色像素不会当作可见红色内容。
- 每镜 checkpoint、取消、恢复指纹、模型与阈值变化、人工/已确认字段保护与历史。
- 非有限数、越界情绪、失效证据 ID、重叠时间、证据路径、资产身份与图片时间语义校验。
- API token、跨站/Host 拒绝、revision 冲突、同内容写锁、原文件替换检测、HTTP Range、导出及 CSV 公式转义。

这些测试验证代码行为，不等同真实影片上的切镜召回率或语义准确率。

## 真实媒体与本地模型

使用电脑中已有素材，只读原件，验证衍生物和日志留在被忽略的 `qa-output/` 与 `runtime/`，不随源码发布。

| 项目 | 实际结果 |
| --- | --- |
| H.264 屏幕录制短片 | 1 镜、5 帧证据；本地模型识别到文件资源管理器和缩略图列表，记录校验通过。 |
| 动画片段（8 秒） | 6 个检测段；4 段有画面内容，2 段各 3 帧的全黑插入。最终 6/6 处理完成；黑帧全字段保持 null，标记 `vision_status=abstained`。 |
| 继续同一动画片段 | 配置指纹不变时，实际模型 HTTP 调用数为 0，记录校验通过。 |
| 动态警示条（20 秒） | 初版差分误切 25 段，调整局部运动/直方图条件后降至 8 段。仍可能把文字闪变当成边界，未宣称全部边界达到导演真值。 |
| JPEG 图片 | CLI 与工作台分别导入成功；没有伪造视频时长。 |
| MOV | 在干净环境中的 wheel 完成测量，生成 H.264 播放代理。 |
| 本地 OCR | 已运行 RapidOCR，返回文字与归一化区域；仅证明该适配器可运行，不代表完整字幕准确率。 |

本地模型为已有 Ollama `qwen3.5:9b-q4_K_M`，没有下载权重，也没有使用云端计费服务。最初出现 JSON 截断；诊断显示默认 4096 上下文被 `3499` 输入 token 与 `597` 输出 token 占满，`done_reason=length`。修复为明确 8192 上下文、紧凑响应格式、输出终止检查和一次受控重试。未知字段继续保持 null；模型未报告的置信度保持 null，不能把它补成“高准确率”。

## 可见界面

在 Codex 浏览器实际操作：

- 本机界面加载；导入对话框自动发现本地模型，可取消 AI 只测量。
- 通过界面导入真实 JPEG，看到运行到完成的任务状态与素材记录。
- 编辑画面描述并确认；文件 revision 递增，来源为 human，原值进入历史，重开后保留。
- 在显示图像上拖动矩形、命名并保存；落盘为归一化 xywh 与对应关键帧 ID。
- 视频真实播放（`paused=false` 且时间前进），点击第 3 镜后 `currentTime=4.75` 秒、`readyState=4`。
- 深链接携带素材与镜头 ID；窄屏 390 像素检查无横向溢出，检查器可继续滚动操作。
- 浏览器错误日志为空。快速导航的过期响应、待跳转目标和刷新位置还通过 JS 定向场景检查。

该播放器未做专业 NLE 级的所有编码帧精确认证。
