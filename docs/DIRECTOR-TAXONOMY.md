# 导演分析字段与词汇草案

这是 FMP 0.1 的字段解释和标注建议，不是唯一的电影理论体系，也不表示当前自动模型能准确识别所有项目。词汇用于检索、比较与复核，允许补充自然语言。导演判断有上下文和审美立场，应保留依据与修订。

所有下列 `analysis.*` 和 `emotion.*` 字段都是 [协议中的 Claim](PROTOCOL.md)。未分析填 `null`；视觉推断标记 `inferred`；人工改写标记 `human`。除下文列明的媒介交换代码外，词表主要是建议表达，允许自然语言补充。

FramePulse Open 应用 0.2 新增媒介、主题和整片汇聚；交换记录的 `spec_version` 仍为 `0.1.0`。它们是可选字段，旧记录缺失这些字段不代表内容被判定为“没有主题”或“不是动画”。

## 1. 当前字段

| 字段 | 要回答的问题 | 建议表达与检索词 | 不能偷换的含义 |
| --- | --- | --- | --- |
| `summary` | 本镜头实际可见的主体、动作和变化是什么？ | 1–3 句具体描述，例如“人物从右侧进入，停在窗边，最后转头看向画外”。 | 别用“高级、电影感、震撼”代替内容；未见过程不要编写先后。 |
| `shot_size` | 主要主体在画面中占据多大范围？ | `extreme_wide` 大远景、`wide` 远景、`full` 全景、`medium_long` 中远景、`medium` 中景、`medium_close` 中近景、`close_up` 近景/特写、`extreme_close_up` 大特写、`detail` 细节。可补中文依据。 | 景别相对主体而定；没有明确主体时保留不确定，不机械套人像裁切规则。 |
| `camera_angle` | 视点与主体的高低、方向关系？ | 平视、俯拍、仰拍、顶视、低机位、斜侧、背面、倾斜地平线；写明参照主体。 | 高机位不必然等于俯拍；“压迫感”是解释，不是角度。 |
| `composition` | 主次关系、视觉重心、空间层次如何组织？ | 对称/不对称、中央/偏置、负空间、框中框、前中后景、引导线、遮挡、视线空间、头顶空间、地平线位置。 | “三分法”不是优劣评分；应说明哪一主体和哪一条线。 |
| `camera_movement` | 画面视点如何随时间变化？ | 固定、pan 摇、tilt 俯仰、dolly 推拉、truck 横移、pedestal 升降、orbit 环绕、roll 旋转、handheld 手持、zoom 变焦、复合运动。 | 主体移动不是摄影机移动；推轨与变焦凭稀疏帧常无法确定，不能强行细分。 |
| `subjects` | 可见主体有哪些，谁是主要主体？ | 人物/物体/动物/环境元素及可见属性；可关联区域 ID。 | 身份未知就用可见描述；不要由衣着猜职业、由外貌猜真实身份。 |
| `actions` | 主体做了什么，动作如何展开？ | 进入、停顿、转身、抬手、接触、追逐等；多帧证据可描述起始、变化、结果。 | 姿态不等于动作过程；“准备攻击”“决定离开”通常包含意图推断。 |
| `setting` | 画面呈现什么环境和时空线索？ | 内/外景、空间类型、天气、可见时代/地域线索；不确定部分单独注明。 | 拍摄地点、故事地点、画面推测地点应区分。 |
| `lighting` | 可见光如何塑造主体与空间？ | 光向、软硬、明暗分布、反差、轮廓光、可见实景光源、局部色光、阴影结构。 | 不能仅凭画面确认灯具型号、照度或真实布光图。 |
| `color` | 主导颜色、饱和度和色彩关系是什么？ | 主色/强调色、冷暖关系、肤色与环境色关系、饱和/克制、色彩对比。 | 像素统计可测，调色意图通常是推断；不能凭观感编造 LUT 或摄影机型号。 |
| `narrative_function` | 镜头在已知上下文里承担什么功能？ | 建立空间、交代关系、行动推进、反应、信息揭示、插入、转折、过渡、情绪停顿、意象、呼应。 | 没有前后文时只能提出候选；一个镜头可以承担多种功能。 |
| `tags` | 下游怎样快速检索这一镜头？ | 使用具体可复用短语，如“雨夜”“反射”“背影”“推近”“红色强调”。 | 不复制整段文案；不要把 AI 自信、人工复核和版权状态塞进内容标签。 |
| `visual_medium` | 画面呈现何种视觉媒介？ | 当前适配器归一化为 `2d_animation`、`3d_animation`、`live_action`、`mixed`、`screen_capture`、`graphic`、`unknown` 或 `null`；中文含义见下表。 | 写实外观不能证明实拍；平面风格不能证明二维制作。该字段描述视觉证据所支持的判断，不是制作工程溯源。 |
| `themes` | 可见内容支持哪些主题词？ | 数组，例如“成长”“城市生活”“对抗”“自然”；未知为 `null`。需要对应人物行为、场景或明确画面线索。 | 主题是概括性推断；一个孤立的红色画面不能自动代表“革命”，动作激烈也不能自动代表完整的复仇故事。 |

景别英文字母缩写在不同工作室中存在差异，因此交换时优先保留完整词和中文解释。IPTC VMH 已提供 Video Shot Type 概念，但这不意味着上述细分值就是它的官方封闭词表。[IPTC VMH Properties：Shot Type](https://iptc.org/std/videometadatahub/recommendation/IPTC-VideoMetadataHub-props-Rec_1.7.html)

### 1.1 媒介代码的使用边界

| 代码 | 中文展示 | 可表达的判断 |
| --- | --- | --- |
| `2d_animation` | 二维动画 | 证据支持以二维动画呈现；不是对绘制软件或制作管线的确认。 |
| `3d_animation` | 三维动画 | 证据支持三维动画/CG 呈现；无法仅凭一帧确定建模、渲染器或实时/离线制作。 |
| `live_action` | 实拍 | 有足够画面依据支持实拍判断；高度写实 CG 与合成仍可能造成误判。 |
| `mixed` | 混合媒介 | 同一分析单元中有明确的多种媒介组合线索。 |
| `screen_capture` | 屏幕录制 | 画面显示桌面、应用或界面的采集内容；不能据此推导画面内播放素材的制作方式。 |
| `graphic` | 图形设计 | 信息图形、标题、平面/动态图形等呈现。 |
| `unknown` / `null` | 未知 | 无法可靠归类；下游不得自动回退为实拍。 |

应用的视觉适配器只输出这些受支持代码；非标准模型返回值被置为未知。需要更细制作分类的调用方应保存有命名空间的扩展，不应擅自把“手绘质感”“二渲三”“AIGC”当成已测得的制作事实。整片 `overview.analysis.visual_medium.value` 是来自已有镜头的代码数组，例如 `["2d_animation","live_action"]`，不会把整片强制压成单一类型。

### 1.2 镜头判断与整片概要

可选 `overview.analysis` 包含 `summary`、`visual_medium`、`themes`、`narrative`、`tags`、`subjects`，均沿用 Claim。当前应用用已有镜头结果摘录、去重和汇聚，保留镜头 ID 与证据，不另行生成未被镜头描述支持的全片剧情。长片概要的摘要条数有上限，不能当成完整分场本。

`summary` 回答“已标注部分主要看到了什么”；`narrative` 保存带镜头编号的原有用途推断。两者都不能回答尚未分析的声音内容或人物真实意图。先看 `overview.coverage` 的语义覆盖、弃答与失败数量，再判断概要能支持多大范围的检索。`completed` 表示分析尝试完成，不是所有语义都已确认；全黑过渡可以完成处理并合法弃答。

## 2. 分析应精确到证据允许的程度

同一个镜头至少有三个层次，写入时应识别自己处在哪一层：

| 层次 | 例子 | 对应处理 |
| --- | --- | --- |
| 可直接测量/读取 | 时长 2.4 秒、宽高、源编码、某区域平均颜色。 | 记录实际算法/元数据来源；有误差就保留误差说明。 |
| 可见内容识别 | 画面中有两个人，右侧人物抬起手。 | 需要对应图像/多帧证据；仍可能识别错误。 |
| 视听或叙事解释 | 右侧人物掌握主动，留白制造不安。 | 明确是解释，保留上下文、低置信和人工修订空间。 |

`origin=measured` 不能用来包装所有“机器生成”的输出。识别对象、景别、摄影机运动和叙事含义通常应标为 `inferred`；算法算出的时间、直方图或元数据读取结果才属于实际测量。

一个静止关键帧能支持构图描述，却不能独立证明摇镜、跟拍、拉焦或动作节奏。当前三个档位都测量全部解码帧；`fast`、`balanced`、`detailed` 分别按 3/5/7 个时间区间选取质量较好的实际帧，并提高相应的视觉输入尺寸。短镜头只使用可用帧，图片只有一个实际图像。更多抽样能提供跨时间观察，但不保证包含每个动作变化点。抽样不足时应写“无法确认”或 `null`，不能用模板补齐。

快速档目前仍请求完整的当前导演字段；它通过较少证据和较小图像控制成本，不能理解为每个字段都有同等质量。应用 0.2 的单视频上限为 45 分钟，这是处理边界，不是电影语言或 FMP 协议的边界。没有语义的测量记录、明确弃答以及部分失败，应与可检索的有效语义分开显示。

## 3. 情绪与节奏

`emotion.valence` 表示氛围的正负倾向，`emotion.arousal` 表示激活程度，`emotion.tension` 表示叙事紧张度。全部使用 0–1 量表；valence 的中点 0.5 表示中性或正负混合，未知不是 0.5，而是 `null`。

“欢快”可以是正向、高激活；“安宁”是正向、低激活；“压抑”可能是负向、低激活；“恐慌”可能是负向、高激活。一个静止长镜头也可以非常紧张，快切也可能轻松。因此节奏、激活度和紧张度需要独立保存。

0.1 的情绪对象是作品所呈现的氛围。它不自动等同角色内心、创作者意图或观众的实测心理反应。动画、游戏 PV 和广告中，音乐、信息揭示、特效密度和品牌叙事会改变解读；若模型只看到静帧，应在结论中说明它没有完整声音和动态上下文。EmotionML 对维度、模态与关联主体的分离为后续扩展提供依据。[W3C EmotionML 1.0](https://www.w3.org/TR/emotionml/)

镜头时长分布和切镜频率可以作为节奏的可测基础。真正的导演节奏还需要动作速度、视觉变化、声音结构、停顿和镜头之间的相互关系；0.1 不把这些尚未分析的维度合并成一个“客观情绪分”。

## 4. 空间标记如何服务导演

区域应指向明确的可见内容：主角、道具、文字、视觉焦点或待讨论的构图区。标签宜写“画面左下方红色道具”，而不是无法复核的“重要元素”。可用多个区域表达主次，但不要由框的大小自动推断叙事重要性。

区域只对其证据帧有效。镜头中角色移动后，旧框不再等于新位置；跨帧跟踪必须另有时间变化的数据。归一化矩形适合第一版快速定位，不能表达复杂轮廓或遮挡；未来可以映射到 IPTC 区域边界或 W3C SVG selector。[IPTC Image Region / Region Boundary](https://iptc.org/std/photometadata/specification/IPTC-PhotoMetadata-2025.1.html)、[W3C Web Annotation §4.2.7](https://www.w3.org/TR/annotation-model/)

应用 0.2 的视觉请求会指定一个证据锚点，并要求尽可能框出 1–4 个主要可见人物/物体；无法确认时仍允许空数组。自动语义框的 `extensions.source="vision"`、`extensions.tracking=false` 明示它没有连续追踪。检视时应停在或显示框所对应的关键帧，并允许跳转至该时刻；视频继续播放后不应把静止框持续罩在运动人物上。OCR 字框解决“哪里有文字”，语义主体框解决“哪里是某个可见实体”，两者不能混为同一种识别结果。

透明图片的证据预览使用注明的中性灰底；该底色不是素材中的场景/道具。完全透明时没有有效可见像素，隐藏的 RGB 值不能成为内容标注。

## 5. 人工复核不是全部重做

推荐先处理 `failed`、缺少证据、低信心、切镜边界可疑和后续检索高频使用的镜头。复核界面应让导演从字段直接看到证据和定位，快速确认、纠正或拒绝。

`accepted` 表示某人接受当前结论，不意味着它成为不可争议的事实；`edited` 表示人工已经改写。当前重新分析保护已认可、已编辑和已拒绝的镜头；重新切镜前保存原镜头记录，边界改变而无法匹配的人工记录进入归档，不自动按序号套用。系统应让机器承担重复劳动，把人的注意力留给歧义、故事语境和审美判断。

## 6. 后续导演扩展：目前不属于已实现能力

下面是跨产品交换需要预留的专业方向。它们应通过有版本的 `extensions` 或正式新协议版本进入，不能通过随意新增同名字符串形成不兼容私有格式。

| 扩展方向 | 应表达的细节 | 主要证据需求 |
| --- | --- | --- |
| 镜头边界与转场 | 硬切、叠化、淡入淡出、擦除、遮挡切；转场起止区间及不确定范围。 | 边界前后的连续帧，必要时声音。 |
| 运动与调度 | 摄影机/主体独立轨迹、画内方向、速度变化、入出画、机位关系。 | 连续时间证据；坐标随时间变化。 |
| 视线与连续性 | 视线目标、轴线、动作匹配、视线匹配、空间关系、反打关系。 | 相邻镜头共同上下文；不能从孤立帧断言。 |
| 光学与焦点 | 景深观感、对焦主体、拉焦发生区间、畸变线索、运动模糊。 | 多帧或源摄影元数据；焦段只能在有来源时作为技术事实。 |
| 声音与声画关系 | 对白、音乐、音效、环境声、画内/画外声、J/L cut、节拍点、同步/对位。 | 可引用的音频区间、转写及声源判断。 |
| PV / 动画节奏 | 起势、蓄势、爆发、收束、动作重拍、特效峰值、信息密度与字幕阅读时间。 | 时间段、运动、声音和文字的联合证据。 |
| 场景与段落 | 场景/sequence 分组、同一地点或事件、平行蒙太奇、段落目的。 | 多镜头关联，保留分组依据。 |
| 文字的时间与语言扩展 | 当前已支持采样帧 OCR 内容和矩形字框；后续增加出现/消失区间、语言、跨帧去重和转写校正。 | 字框或音频；OCR 检出不等于文字已被准确读出。 |
| 多种解释共存 | 不同导演/模型对叙事作用、意象和情绪的不同看法。 | 独立作者、上下文、版本和证据，不能简单取平均。 |
| 权利与来源 | 原作者、转载来源、素材授权、下载来源及使用限制。 | 来源记录与显式许可；画面内容不能推导授权。 |

这些扩展以可核验的信息为准逐步加入。首要验收标准是下游能够正确回到原素材、原镜头和证据位置，并能区分机器判断与人工决定。
