# 架构与路线图

## 0.1 分层

`media.py` 解码/测量/关键帧，`providers.py` 视觉模型与 OCR 适配，`engine.py` 编排与恢复，`protocol.py` 校验/存储/交换。`cli.py` 可独立运行，`server.py` 提供 loopback API，`web/` 只使用该 API。界面不是 AI 执行或文件格式的依赖。

SHA-256 目录是内容寻址，不是相似性搜索。文件锁串行化同素材写入；JSON 原子替换保证读取不遇到半份文件。人工修订存前值，AI 成功逐镜保存。UI 读写使用 revision；HTML 中媒体文本当文本处理，不能执行素材里的指令。

SQLite/向量库不是协议必需品。宿主可以把 sidecar 投影到自己的数据库。将来加入数据库时仍以文件格式可独立读取、可重新索引为约束。

## 专业下一阶段

1. 用真实 PV、动画、纪录、广告构建有人工真值的切镜/字段数据集；统计漏切/误切、时间误差、字段正确率。第一优先是质量测量，而非增加模型文案。
2. 人工修订镜头边界、渐变转场、动作段分割，保留旧镜头与新镜头的对应关系；不按序号盲搬人工标记。
3. ASR/声音事件/音乐节拍独立证据轨，与画面情绪分离；日本语等 OCR provider 扩展。
4. 帧内区域跟踪和主体跨镜连续性；每段轨迹必须有有效时间，不能把单帧检测宣称为追踪。
5. OTIO Marker/Clip 与 IPTC/XMP 基础字段适配；跨编码 representation、代理变换、共享 asset URI。
6. 规范治理：带版本的 JSON Schema、迁移工具、参考文件、下游兼容测试与提案流程。公开征集真实工作流再稳定为 1.0。

不计划在这个核心引擎中重做素材下载器、全量批次调度器或完整 NLE。FlowDesk 和其他产品可以围绕它构建这些能力。
