# Ollama 接入：从首次下载到更换模型

帧脉不带模型权重。模型由 Ollama 下载、存放和运行；帧脉通过本机 HTTP 接口提交证据帧，读取结构化分析结果。APP、CLI 和 FlowDesk 调用共用分析引擎。

## 第一次使用

1. 按 [README](../README.md#下载与启动windows-app) 安装并打开桌面 APP。
2. 从 [Ollama 官网](https://ollama.com/download) 安装 Ollama 并启动。Windows 通常会在托盘运行；普通用户不用手动运行 `ollama serve`。
3. 打开 [官方视觉模型列表](https://ollama.com/search?c=vision)，选择明确支持图片输入的**本地**模型。不要选择仅文本模型；带 `cloud` 的模型在云端运行。选择大小时考虑自己的显存、内存和速度需求，参数量更大不表示更适合批处理。
4. 在 Windows 终端 / PowerShell 执行模型页面提供的下载命令。比如已实测的轻量候选：

   ```powershell
   ollama pull qwen3.5:4b-q4_K_M
   ollama list
   ```

   这个示例是历史实测型号，不承诺它永远是最新款。今后可以直接换成官方模型页面当前的完整名称。第一次会下载数 GB 或更多，等待完成再分析。

5. 帧脉启动时自动连接 `http://127.0.0.1:11434`，读取已安装模型及视觉能力。初次未配置且服务尚未就绪时，每 20 秒重试；不用关闭 APP 等下载。
6. 在「模型与分析设置」核对选中的模型。自动选择规则是**最近安装/更新的本地视觉模型**，不是模型能力排名。开启「默认启用 AI 内容分析」后拖入素材，点击「开始队列」。建议先分析一张图片，检查结果再跑大批量。

模型设置只影响之后加入的任务。已排队任务保留入队时的模型和档位；需要新模型时取消旧待处理任务并重新导入。关闭 AI 时仍可拆镜和读取技术信息，但不会生成内容语义。

## 更换或升级模型

1. 更新 Ollama 应用，支持新架构需要较新的运行时。Windows/macOS 的 Ollama 更新下载后通常需要重启应用；也可从官网下载当前版本。[官方更新说明](https://docs.ollama.com/faq)
2. 在终端执行 `ollama pull 完整模型名:标签`。重复 pull 已有标签会检查更新；选择新型号时使用新型号的完整名称。
3. APP 内打开设置，点击「刷新列表」，选择新模型并「保存设置」。也可点击「自动连接并保存」采用最近安装/更新的本地视觉模型。
4. 已保存的手动选择不会在后台被替换；AI 关闭也不会被后台擅自打开。显式点击「自动连接并保存」会改用本地模型并开启 AI。

帧脉通过 `/api/tags` 和 `/api/show` 的 `capabilities` 发现视觉模型，不依赖写死的品牌或版本名单。新模型只要由当前 Ollama 正确报告视觉能力，就能进入列表；是否稳定遵循 JSON Schema、是否准确识别具体画面，仍需实际验证。分析失败会保留错误与恢复状态，不会用虚构结果填满字段。

## 自动连接失败：手动配置

在「模型与分析设置」把模型来源改为「手动配置 · 自定义 Ollama / 兼容服务」：

| 字段 | 普通本机 Ollama 填法 |
| --- | --- |
| 服务地址 | `http://127.0.0.1:11434/api` |
| 视觉模型名称 | `ollama list` 输出的完整 NAME，例如 `qwen3.5:4b-q4_K_M` |
| API 密钥 | 留空，除非自己的代理明确要求 |
| 默认启用 AI | 开启后保存 |

如果 Ollama 使用自定义端口，把 `11434` 替换成实际端口，并保留 `/api` 后缀；这会选择 Ollama 原生协议。远程 Ollama 同理使用自己的完整地址加 `/api`；其他兼容服务一般使用服务商提供的 `/v1` 地址。选择远程服务时，证据图片会被发送到那个地址。密钥仅在当前进程内保存，重启后需重新输入。

程序不会扫描局域网、修改防火墙、自动下载模型或启动另一个 Ollama 服务。云端别名即便通过本机 Ollama 暴露，也不会被自动选作本地模型。若你确实要用云端模型，需要明确手动填写并启用。

## 常见情况

| APP 中的表现 | 处理步骤 |
| --- | --- |
| 无法连接模型服务 | 启动 Ollama，确认托盘图标；点击「自动连接并保存」。在浏览器访问 `http://127.0.0.1:11434/api/tags` 能返回 JSON 则服务可达。 |
| 已连接，但没有本地视觉模型 | 等待 pull 完成，执行 `ollama list` 检查；纯文本模型无法用于图片分析。 |
| 无法确认视觉能力 | 更新 Ollama 后刷新。仅当已确认模型支持图片时才手动填写名称；软件不会把未知能力当成确定支持。 |
| 模型不在刷新列表里 | 确认下载模型和 APP 连接的是同一个 Ollama 实例 / 端口 / Windows 用户。列表最多读取 64 个安装条目，超出时可手动填写。 |
| 能连接但分析超时 / 显存不足 | 先试单张图和「快速」档，换较小的量化视觉模型。用 `ollama ps` 查看加载状态；大量 CPU 卸载会降低速度。 |
| 模型输出不是有效 JSON | 更新 Ollama 或换用遵循结构化输出的视觉模型，再重试；仅出现于列表不等于已经通过质量验收。 |
| 设置换了模型，队列仍显示旧模型 | 队列保留入队配置；取消并重新导入需要改模型的待处理任务。 |

## CLI / FlowDesk

自动检测默认本机 Ollama：

```powershell
.\framepulse.cmd analyze 'D:\素材\海报.png' --output 'D:\媒体标记库'
```

显式指定本地实例和模型（不依赖 APP 的设置）：

```powershell
$env:FRAMEPULSE_PROVIDER_URL = 'http://127.0.0.1:11434/api'
$env:FRAMEPULSE_MODEL = 'qwen3.5:4b-q4_K_M'
.\framepulse.cmd analyze 'D:\素材\参考.mp4' --vision --profile fast --output 'D:\媒体标记库'
```

不希望 AI 参与时显式加 `--no-vision`。FlowDesk 可读 CLI 的 JSON 输出和逐行进度；详见 [集成契约](INTEGRATION.md)。

实现依据：[列出本地模型](https://docs.ollama.com/api/tags)、[官方 API 定义](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)、[视觉输入](https://docs.ollama.com/capabilities/vision)。
